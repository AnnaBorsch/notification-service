# Notification Service

Микросервис для потребления уведомлений из топиков Kafka, обеспечивающий идемпотентную обработку с помощью паттерна Inbox.

## Технологический стек

- **Java 21**
- **Spring Boot 3.5.x**
- **Apache Kafka**
- **PostgreSQL**
- **Maven**
- **Lombok**

## Функциональность

1.  **Kafka Consumers**
    *   Отдельные слушатели (`@KafkaListener`) для топиков: `sms-events`, `email-events`, `push-events`, `telegram-events`.
2.  **Идемпотентность (Inbox Pattern)**
    *   Каждый consumer перед сохранением проверяет уникальность сообщения по комбинации `key` (ключ сообщения) и `value` (тело).
    *   Если сообщение с таким ключом уже существует в соответствующей inbox-таблице, оно пропускается (логируется как дубликат). Это защищает от повторной обработки при сбоях (At-least-once доставка Kafka).
3.  **Inbox-таблицы**
    *   `sms_inbox`
    *   `email_inbox`
    *   `push_inbox`
    *   `telegram_inbox`
4.  **Шедулер обработки (Processor)**
    *   Для каждой таблицы `inbox` запущен отдельный шедулер.
    *   Периодически (с настраиваемой задержкой `delay-ms`) выбирает пачку (`batch-size`) необработанных (`processed = false`) сообщений.
    *   Симулирует обработку (логирует событие) и помечает запись как обработанную (`processed = true`). При ошибке увеличивает счетчик попыток (`attempt`).
